# Reproducible crypto-agile PQC/QKD migration simulator

This repository accompanies the Original Research manuscript *A Crypto-Agile
Migration Framework for Post-Quantum Cryptography and Selective Quantum Key
Distribution in Carrier Networks* (IET Quantum Communication, manuscript
QTC-2026-07-0055). It is a deterministic, seeded planning and policy
simulator. It does not claim carrier validation, finite-key QKD security,
wire-conformant ETSI interoperability, or production protocol integration.
**No carrier or operator data are used**; every input is generated from fixed
seeds by the code in this repository.

## Implemented scope

- Decisions are made per service/application rather than once per link.
- Migration prioritisation uses a Mosca-style margin: confidentiality lifetime
  plus migration lead time minus planning horizon.
- Modes distinguish PQC-only, post-quantum/traditional (PQ/T) hybrid,
  QKD-assisted, and combined PQ/T+QKD operation.
- HNDL-exposed fail-closed services cannot silently downgrade to
  traditional-only operation.
- QKD route qualification requires a suitable optical path, sufficient approved
  trusted sites, and compliance with a trusted-node policy limit.
- The paired-KME domain model uses key identifiers, matching peer retrieval,
  single-use semantics, and explicit errors. It is not an ETSI GS QKD 014 REST
  server.
- IKEv2, MACsec, and OTN use separate analytical rekey adapters. RFC 9370 and
  RFC 9867 mechanisms are applied only to IKEv2; MACsec and OTN remain generic
  abstractions.
- The event-driven simulator records failures, deadline misses, proactive
  demotions, reactive fallbacks, mode transitions, KME errors, minimum pool
  level, and per-session latency samples.
- The cost model charges QKD endpoint pairs per physical hop, applies common
  orchestration costs to both strategies, discounts cash flows over a
  configurable horizon and rate, and separates shared from incremental cost.
- `PlanningParams` (`hybridsim/params.py`) exposes every planning constant so
  that sensitivity sweeps and comparison baselines are explicit.
- Every manuscript figure is generated by one module in `figures_src/`
  (matplotlib) or one TikZ file (Figure 1, graphical abstract), drawn at the
  printed width in a single-hue style, and checked by a layout lint
  (`hybridsim/figcheck.py`: no titles, no overlapping text, no text below
  8 pt). `figures_src/FIGURE_SPEC.md` is the figure specification.

## Reproduce

```bash
python3 -m pip install -r requirements.txt
python3 run_experiments.py      # reference results (results/*.csv) + Figures 1-6 + graphical abstract
python3 run_sensitivity.py      # 142 scenario runs -> results/sensitivity/*.csv (~3 min)
python3 make_figures.py         # Figures 7-10 from the sensitivity CSVs
python3 build_figures.py        # (re)build any figure: build_figures.py 4 7 GA
PYTHONPATH=. python3 -m pytest -q
```

Seeds are fixed in code: topology 7, event simulation 11, negative control 23.
Outputs are written to `figures/` (600-dpi PNG, LZW TIFF and vector PDF) and
`results/`. Figure 1 and the graphical abstract are TikZ drawings and need a
TeX distribution with `pdflatex`, `tgheros` and `pdftoppm` (poppler); the
committed PNG/PDF/TIFF files are the published versions, so the matplotlib
figures and all results reproduce without TeX.

## Layout

```
hybridsim/
  params.py       planning parameters (PlanningParams)
  topology.py     seeded synthetic topology and service contexts
  qkd.py          attenuation-envelope route planner
  kms.py          paired-KME domain model, reserve-time and dimensioning bound
  policy.py       explainable service-level decision engine
  protocols.py    IKEv2 / MACsec / OTN analytical rekey adapters
  selection.py    phase-3 overlay selection (selective | all_feasible | none)
  simulate.py     event-driven 24-hour fault simulation
  tco.py          cost model with physical-hop accounting and breakdown
  experiments.py  scenario runner used by every script
  plotstyle.py    shared single-hue figure style (fonts, palette, panel letters)
  figcheck.py     layout lint applied to every matplotlib figure
figures_src/      one module (or TikZ file) per figure, captions/, FIGURE_SPEC.md
run_experiments.py, run_sensitivity.py, make_figures.py, build_figures.py
tests/
results/, results/sensitivity/, figures/
```

## Interpretation limits

Performance constants, topology, workloads, repair margins, and costs are
illustrative. Replace them with operator measurements before using the outputs
in an engineering or investment decision. Internet-Draft protocol profiles
must be cited as work in progress and version-checked on the submission date.
